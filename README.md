# อยุธยาเรียนรู้ · SDG 4

เว็บไซต์ Static Site ภาษาไทย 10 หน้า จัดทำเพื่อ บูรพาทิศ พลอยสุวรรณ์ ผู้วิจัยอิสระ ติดต่อ burapatis@gmail.com เพื่อประโยชน์สาธารณะและสังคมแห่งการเรียนรู้

## นำขึ้น GitHub Pages — ไม่ต้อง build

1. แตก ZIP จะได้โฟลเดอร์ `ayutthaya_sdg_website`
2. สร้าง public repository ใน GitHub เช่น `ayutthaya-sdg4`
3. อัปโหลด **ไฟล์และโฟลเดอร์ข้างใน** `ayutthaya_sdg_website` ไปไว้ที่ราก repository ให้เห็น `index.html`, `css`, `js`, `data`, `content`, `downloads` โดยตรง ไม่ซ้อนโฟลเดอร์เพิ่ม
4. รวมไฟล์ `.nojekyll` ด้วย หากระบบอัปโหลดไม่แสดงไฟล์ซ่อน สามารถสร้างไฟล์ชื่อ `.nojekyll` ที่ราก repository ใน GitHub ได้
5. เปิด Settings → Pages → Build and deployment → Source: **Deploy from a branch** เลือก branch `main` และโฟลเดอร์ `/(root)` แล้วกด Save หาก repository ใช้ชื่อ branch อื่นให้เลือกชื่อนั้น
6. รอการเผยแพร่เสร็จและเปิด URL ที่ GitHub แสดง โดยทั่วไปเป็น `https://ชื่อผู้ใช้.github.io/ชื่อ-repository/`
7. ตรวจหน้าหลัก บทความ กราฟ และเมนูมือถือ หากเคยเปิดก่อนแก้ข้อมูล ให้โหลดหน้าใหม่

เส้นทางภายในเป็นแบบสัมพัทธ์ ใช้ได้ทั้ง user site และ project site ไม่ต้องแก้ base URL ไม่มีเซิร์ฟเวอร์ส่วนหลัง ไม่มีฐานข้อมูลบน GitHub Pages และไม่ต้องติดตั้ง Node/Python เพื่อโฮสต์

คู่มือทางการ: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## แก้ไขเนื้อหาโดยไม่แก้ HTML

- บทความ: แก้ `content/*.md`; หัวข้อเริ่มด้วย `##` ใช้ตารางและลิงก์ Markdown ได้
- เพิ่มบทความในคลัง: สร้าง `.md` และเพิ่ม `id`, `title`, `file` ใน `data/articles.json`; ใช้ชื่อไฟล์ปลอดภัยภายใต้ `content/` และ `id` ไม่ซ้ำ
- ข้อมูล Dashboard: แก้ `data/stats.json` แยก `reference` และ `demo`; เปลี่ยน `defaultDataset` ได้ แก้ปี ที่มา ข้อจำกัด และหน่วยพร้อมตัวเลขเสมอ
- `trend.labels` และ `trend.values` ต้องยาวเท่ากัน ใช้ `null` เมื่อไม่มีข้อมูล ไม่ใช้ 0 แทนค่าที่ไม่ทราบ
- จุดแผนที่: แก้ `map.points` และ `map.status`; ตำแหน่งที่ให้มาเป็นเพียงประมาณเพื่อสาธิต หากใช้ข้อมูลจริงต้องตรวจพิกัดและแหล่งที่มา แล้วเปลี่ยนคำอธิบายให้ตรงกัน
- ระบบนิเวศ: แก้ `data/ecosystem.json` คง 4 องค์ประกอบให้ตรงปุ่ม หรือแก้ปุ่มใน HTML เมื่อต้องเพิ่มองค์ประกอบ
- โครงการ: แก้ `data/projects.json` และ `content/projects.md`
- ความเชื่อมโยง: แก้ `data/alignment.json` และ `content/alignment.md`; ตัวกรองสร้างจากข้อมูลให้อัตโนมัติ
- ตัวชี้วัด: แก้ `data/indicators.json`; แสดงนิยามจากข้อมูลเดียวกัน กรอก `baseline`, `baselineYear`, `target`, `targetYear` เมื่อมีข้อมูลและระบุที่มารับรองใน `source`; ค่าจะเปลี่ยนตาม JSON โดยไม่ต้องแก้ JavaScript แต่เว็บไซต์ยังไม่ตัดสินผ่าน/ไม่ผ่านอัตโนมัติ
- เครื่องมือ: แก้ไฟล์ใน `downloads/` และรายการ `data/downloads.json`
- ผู้จัดทำ: แก้ `content/about.md`; ชื่อ/อีเมลในส่วนท้ายของ HTML ให้แก้ทั้ง 10 หน้าด้วยหากเปลี่ยนข้อมูลติดต่อ
- ที่มา: แก้ `data/sources.json` และบทความ `content/source-notes.md`; `data/provenance.json` เก็บชื่อและ SHA-256 ของไฟล์ใน Projects ที่ใช้ในการสร้างฉบับนี้ ไม่ใช่หลักฐานรับรองเนื้อหาต้นทาง

ลิงก์ภายใน Markdown สำหรับแสดงบนเว็บไซต์ให้เขียนจากรากเว็บ เช่น `projects.html` เพราะแสดงเนื้อหาอยู่ในหน้า HTML ที่ราก ส่วนเอกสารอ้างอิงภายนอกควรใช้ URL เต็ม

JSON ต้องใช้เครื่องหมายคำพูดคู่ ไม่มีคอมเมนต์หรือ comma หลังรายการสุดท้าย บันทึก UTF-8; ตรวจไฟล์ได้ด้วย `python3 -m json.tool data/stats.json` ถ้ามี Python

## เปิดเว็บตัวอย่างบนเครื่อง

ไม่แนะนำดับเบิลคลิก HTML เพื่อเปิดแบบ `file://` เพราะเบราว์เซอร์อาจไม่อนุญาตให้โหลด Markdown/JSON

หากมี Python ให้เปิด terminal ในโฟลเดอร์เว็บไซต์ แล้วใช้ `python3 -m http.server 8000` จากนั้นเปิด `http://localhost:8000` หรือใช้ local server ของโปรแกรมแก้ไขเว็บไซต์ หากไม่มี Python สามารถอัปโหลดขึ้น GitHub Pages ตามขั้นตอนแรกได้เลย

## เปิดใช้งาน Giscus

ค่าเริ่มต้นปิดไว้เพราะยังไม่มี repository ของผู้ใช้ เว็บไซต์แสดงข้อความสถานะจริง ไม่มีการแสดงความคิดเห็นจำลอง

1. ใช้ repository สาธารณะ เปิด Settings → General → Features → Discussions
2. เปิด https://giscus.app/th ติดตั้ง GitHub App ตามคำแนะนำ และเลือก repository/category สำหรับพื้นที่สนทนา
3. คัดค่า `data-repo`, `data-repo-id`, `data-category`, `data-category-id` ที่ Giscus สร้าง ไปใส่ `repo`, `repoId`, `category`, `categoryId` ใน `data/site.json`
4. เปลี่ยน `enabled` เป็น `true` แล้วบันทึกขึ้น GitHub
5. เปิด forum.html กด “เปิดพื้นที่สนทนา Giscus” และทดสอบเข้าสู่ระบบ/ส่งความคิดเห็นด้วยบัญชีของคุณ

การตั้งค่ารายการข้างต้นเป็น identifier สาธารณะ ไม่ต้องใส่ GitHub token หรือรหัสผ่านในเว็บไซต์ Giscus ใช้ pathname จับคู่บทสนทนา หากเปลี่ยน URL ของหน้าภายหลังให้ตรวจการจับคู่ใหม่ ผู้จัดทำดูแลความเห็นผ่าน GitHub Discussions

## แหล่งข้อมูลและสถานะ

- ใช้เอกสารใน Projects 02, 03, 16, 17 และข้อมูลหกโครงการจากเว็บไซต์เดิม ประกอบแหล่งทางการ UN, CAST, UNESCO, OECD และราชกิจจานุเบกษา

- ตัวเลขอ้างอิงย้อนหลังไม่ใช่ค่าฐานปัจจุบันที่รับรอง ชุดจำลองไม่ใช่สถิติราชการ โครงการและตัวชี้วัด I01–I10 เป็นข้อเสนอพร้อมปรับใช้ ไม่ใช่มติอนุมัติ
- เครื่องมือประเมินยังไม่ผ่านการตรวจคุณภาพภาคสนาม ให้ทดลองภาษา ความตรง ความสอดคล้องผู้ประเมิน และการเข้าถึงก่อนใช้จริง
- เอกสารต้นฉบับใน Projects ไม่ถูกแก้ไข ไม่มีข้อมูลผู้เรียนรายบุคคลอยู่ใน ZIP

## เทคโนโลยีและการเชื่อมต่อ

ใช้ HTML/CSS/JavaScript, Tailwind CSS ผ่าน Play CDN ตามคำขอ, Chart.js 4.4.8, Leaflet 1.9.4, marked 15.0.12 และ DOMPurify 3.3.1 เพื่อกรอง HTML ที่แปลงจาก Markdown มี CSS หลักใน `css/style.css` รองรับการจัดหน้าหลักเมื่อ Tailwind ไม่โหลด

ไลบรารี CDN, ฟอนต์ Google, แผนที่ OpenStreetMap และ Giscus ต้องใช้อินเทอร์เน็ต GitHub Pages โฮสต์ได้โดยไม่ต้อง build แต่ไม่ใช่เว็บออฟไลน์ 100% หาก Chart.js ไม่โหลดจะมีตารางแทน ถ้าแปลง Markdown ไม่ได้จะอ่านเป็นข้อความต้นฉบับ และมีข้อความแจ้งเมื่อโหลดข้อมูลไม่สำเร็จ

Tailwind ระบุ Play CDN สำหรับการพัฒนา ในชุดนี้คงไว้ตามข้อกำหนดผู้ใช้; หากต้องการลดการพึ่งพาภายนอกในอนาคตสามารถสร้าง CSS ล่วงหน้าและโฮสต์ไลบรารีเองได้ โดยคงผลลัพธ์เป็น static site

ให้คงเครดิต OpenStreetMap บนแผนที่ และอ่านนโยบายบริการเมื่อมีการใช้งานจำนวนมาก: https://operations.osmfoundation.org/policies/tiles/

คู่มือไลบรารี: https://www.chartjs.org/docs/latest/ · https://leafletjs.com/ · https://marked.js.org/ · https://github.com/cure53/DOMPurify · https://tailwindcss.com/docs/installation/play-cdn

## การเข้าถึงและข้อมูลสาธารณะ

รองรับเมนูมือถือ แป้นพิมพ์ จุดโฟกัส ลิงก์ข้ามเนื้อหา ตารางประกอบกราฟ การลดการเคลื่อนไหว และการพิมพ์ ใช้คำอธิบายข้อความประกอบสถานะ ไม่อ้างการรับรอง WCAG อย่างเป็นทางการ เครื่องคำนวณร้อยละไม่บันทึก/ส่งค่าที่กรอก ไม่เผยแพร่ข้อมูลรายบุคคลใน JSON สาธารณะ

## ตรวจหลังแก้ไข
